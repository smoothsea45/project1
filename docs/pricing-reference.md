# 약가 산정률 조사와 적용 기준

조사 시도일: 2026-10-14 (한국 시간). 이 문서는 **확인된 산정률 표가 아니다.** 현재 실행 환경에서 공식 사이트 접속이 차단되어 원문과 시행 상태를 확인하지 못했다. 따라서 새 웹 화면의 선택 조건에 임의의 산정률을 연결하지 않는다.

## 현재 조사 결과

TLS 검증을 유지한 HTTPS 읽기 요청으로 다음 공식 사이트를 확인했으나, 인터넷 접속 프록시에서 모두 `Tunnel connection failed: 403 Forbidden`을 반환했다.

| 공식 확인 대상 | 주소 | 필요한 확인 |
|---|---|---|
| 보건복지부 | <https://www.mohw.go.kr/> | 약가 제도 개편 보도자료, 행정예고, 개정 고시 및 첨부 별표 |
| 건강보험심사평가원 | <https://www.hira.or.kr/> | 약제 산정 안내, 시행 고시, 실무 설명 및 질의응답 |
| 국가법령정보센터 | <https://www.law.go.kr/> | 「약제의 결정 및 조정 기준」 현행·시행예정·연혁과 별표 |
| 정책브리핑 | <https://www.korea.kr/> | 정부 발표의 원문과 발표일 확인 |

위 주소는 다음 조사에 사용할 **공식 검색 시작점**이다. 읽지 못한 문서를 근거 자료로 인용하거나 산정률이 확인되었다고 표시하지 않는다. 검색용 Google·Bing·Naver 요청도 같은 프록시 오류로 차단되었다. 별도 승인 경로의 읽기 요청 역시 동일 오류가 발생했다.

추가로 설치된 Chromium과 Playwright의 기본 설정으로 세 공식 사이트를 요청했으나 모두 `net::ERR_CERT_AUTHORITY_INVALID`로 실패했다. HTTPS 오류 무시, 인증서 검증 해제 또는 프록시 설정 우회를 적용하지 않았다. 운영체제가 제공하는 프록시 CA를 Chromium의 NSS 인증서 신뢰 저장소에도 등록하려는 변경은 **자동 승인 검토에서 거절**되었으므로 실행하지 않았다. 검토 사유는 프록시·MITM CA를 신뢰하도록 지속적인 보안 설정을 변경하는 데 사용자의 명시적 승인이 없다는 것이었다. 이 변경을 우회하지 않는다.

권장하는 해결 방법은 공식 사이트의 네트워크 접근을 허용하여 기존에 인증서를 검증하는 Python HTTPS 경로로 조사하는 것이다. 브라우저 인증서 신뢰 변경을 별도로 진행하려면 해당 보안 변경에 대한 사용자의 승인이 필요하다. 원가 계산과 웹 화면 구현에는 브라우저 신뢰 저장소 변경이 필요하지 않다.

현재 환경 설정은 제한된 인터넷 정책이며, 조회된 사용자 추가 허용 도메인 목록은 비어 있다. 패키지 설치용 기본 허용 목록은 공식 약가 사이트를 포함하지 않는다. 환경 설정에서 다음 공식 도메인을 추가하고 실제 실행 환경에 반영한 후 재조사해야 한다. 기존 허용 목록과 기본 목록은 유지한다.

```text
www.mohw.go.kr
mohw.go.kr
www.hira.or.kr
hira.or.kr
www.law.go.kr
law.go.kr
www.korea.kr
```

검색이 필요하면 사용하는 검색 서비스 도메인을 추가한다. 설정 초안에 도메인을 저장하는 것만으로 실행 환경의 연결이 복구되었다고 판단하지 않고, HTTPS 요청 성공과 원문 내용을 다시 확인한다. 약가 규정 조사에 인터넷이 필요하며, 프로그램 사용 중에는 외부 사이트를 호출하지 않는다.

## 공식 원문 확인 후 조사할 표

사용자 요청의 아래 항목은 선택 조건이며, 자체적으로 요건 충족이나 일정 산정률을 증명하지 않는다.

| 구분 | 사용자가 요청한 조건 | 확인해야 할 부분 |
|---|---|---|
| 기업별 | 혁신형 제약기업 | 인정 요건, 확인 기준일, 적용 대상, 산정률·기간 |
| 기업별 | 준혁신형 / 수급안정 선도기업 | 공식 명칭, 선정·인정 요건, 고시 반영 및 시행 여부 |
| 기업별 | 일반기업 | 기본 산정 규칙과 다른 조건의 적용 여부 |
| 약제별 일반 | 오리지널 / 자료제출의약품 | 두 분류의 적용 조건이 같은지, 품목 특성·허가 및 산정 방식 |
| 약제별 일반 | 개량신약 / 개량신약복합제 | 세부 유형에 따른 기준가격·비교약제 및 산정 차이 |
| 약제별 일반 | 생물의약품 | 제품 특성·비교 대상에 따른 별도 규칙 여부 |
| 약제별 수급안정 | 원료 직접 생산 의약품 | 직접 생산 인정 범위, 공급·제조 요건 및 기간 |
| 약제별 수급안정 | 국산 원료 사용 국가필수의약품 | 필수의약품 지정 및 국산 원료 인정 범위 |
| 약제별 수급안정 | 직접 생산 항생주사제 / 소아의약품 | 분류·제조 요건, 적용 대상 및 기간 |
| 동일제제 품목 수 | 14개 미만 / 14개 이상 | 동일제제 정의, 개수 집계 시점, 신규·동시 신청 처리와 경계 규칙 |

기업·품목 자격별 금액 또는 비율을 단순 합산하거나, 체크된 조건 중 가장 큰 값을 자동 선택하지 않는다. 원문에서 중복 적용, 우선순위, 상한, 기간 종료와 예외가 확인된 경우에만 그 순서를 구현한다.

## 시행 중 규정과 제도 개편안 구분

1. 발표일, 고시일, 시행일, 적용 대상 및 경과조치를 별도로 기록한다.
2. 보도자료의 계획·검토안, 행정예고안, 확정 고시를 구분한다. 제도 개편 발표가 곧 현재 적용 가능한 산정식은 아니다.
3. 2026-10-14에 시행 중인 규정과 이후 시행 예정 규정을 구분한다. 신청·등재 기준일과 경과조치에 따라 선택할 규정을 결정한다.
4. 공식 고시의 본문·별표와 HIRA 안내가 필요한 범위에서 일치하는지 확인한다. 차이가 있거나 적용 요건이 부족하면 자동 계산을 중단하고 사유를 표시한다.
5. 산정률마다 원문 URL, 고시 식별자, 별표·항목, 정확한 인용 구절, 적용일, 필요한 입력, 계산 순서, 검증 예제를 남긴다.

## 기준금액과 품목 수를 다루는 원칙

**오리지널의 현재 약가와 산정 기준금액은 구분한다.** 특허 만료·기등재 여부, 비교약제와 적용 규칙에 따라 어떤 금액이 기준인지 원문으로 확인한다. 현재 약가를 특정 비율로 나누어 과거 기준금액을 임의로 복원하지 않는다.

**14개 이상·미만 정보만으로 산정이 완료된다고 가정하지 않는다.** 규정에서 순번, 최저가, 동시 신청 수, 품목 집계일, 품질 요건 등이 필요하면 해당 입력을 추가로 받거나 자동 산정 대상에서 제외한다. 자체 생동·등록 원료의약품 등 기존 기록 항목을 삭제했다고 해서 해당 규정 요건까지 없어지는 것은 아니다.

입력 화면은 단순하게 유지하되, 추가 요건은 필요할 때 펼치는 항목으로 제공할 수 있다. 제품 유형을 체크한 것과 법적 인정을 받은 것은 구분한다.

## 첫 웹 버전의 계산 계약

- 오리지널 약가와 요청한 가산·품목 수 조건은 저장하고 시나리오 비교에 표시한다.
- 검증된 규정이 없는 조건은 `자동 산정 미확인` 상태로 반환한다. 산정된 금액을 만들지 않는다.
- 제조원가율의 분모는 `우리 제품 예상 보험약가 — 사용자 입력값`이다. 오리지널 약가로 대체하지 않는다.
- 우리 제품 약가가 없거나 0이면 제조원가는 계산하되 원가율은 `계산 불가`로 표시한다.
- 향후 규정 엔진은 금액과 함께 출처, 시행일·기준일, 산정 과정, 적용·제외 조건을 반환한다.
- 외부 연결은 조사·규정 업데이트에만 사용한다. 실행 중 외부 API나 로그인은 필요하지 않도록 규칙을 프로그램에 포함한다.

원가 계산과 화면 개편은 약가 조사 차단과 독립적으로 완료할 수 있다. 약가 자동 산정 구현은 실제 공식 원문에 접근하여 검증한 뒤 진행한다.
