# 첫 버전 검증 기록

검증 환경: Linux x86_64, Python 3.12.14, PySide6 6.8.3. 화면은 실제 Qt 위젯을 `offscreen` 플랫폼에서 생성하여 검증했다.

```bash
QT_QPA_PLATFORM=offscreen XDG_CACHE_HOME=/tmp/pharma-cost-cache .venv/bin/python -m pytest
```

결과: **113 passed**.

추가 확인:

- 가상 예제 기본안: API 40원 + 부형제 10원 + 포장재비 10원 + 공수비 20원 = **80원/정**, 약가 300원 대비 **26.67%** (표시값).
- 가상 예제 절감안: **60원/정**, 약가 300원 대비 **20%**, 목표 달성.
- 편집 가능한 설치(`pip install --editable .`)와 설치된 모듈의 프로그램 창 시작·정상 종료를 확인했다.
- `pip check`: 의존성 충돌 없음.
- 제품·약가, 원료, 비용, 결과·차트, 비교 탭을 offscreen 이미지로 렌더링하여 표시를 확인했다.

Windows 배포는 **설정 및 절차 준비** 상태다. 현재 환경에서 Windows `.exe`를 빌드하거나 Python 없는 Windows PC에서 실행하지 않았다. 실제 Windows 빌드 및 오프라인 실행 검증은 [Windows 배포 안내](windows-distribution.md)에 따라 수행해야 한다.

약가 자동 산정률은 구현하거나 검증하지 않았다. 첫 버전의 계산은 사용자 입력 약가만 사용한다.

## 배치 기준 웹 버전 검증

추가 환경: Node.js 24.19.0, 함께 배포한 Decimal.js 10.6.0, Playwright 1.62.0과 시스템 Chromium. Decimal.js 배포 압축파일은 npm 공식 레지스트리의 SHA-512 무결성 값과 일치함을 확인했다. 계산 라이브러리는 실행 중 내려받지 않는다.

```bash
node --test web/tests/engine.test.cjs
.venv/bin/python -m pytest web/tests/test_browser.py
```

- 계산·JSON: **69개 통과**. 배치 기준 네 단가 단위, 공통 환율, 전체 단위 비용 수율 적용, 부분 결과, 복제 원본 유지, 엄격한 파일 검증을 포함한다.
- 실제 브라우저: **29개 통과**. 즉시 입력, 원료표·다중 행 삭제·TSV 붙여넣기, 시나리오 비교, JSON 다운로드·열기, 미저장 확인, 브라우저 초안 복원, 외부 요청 없음과 루트 진입 페이지 이동을 포함한다.
- 기존 데스크톱 테스트 113개와 브라우저 테스트 29개를 함께 실행한 결과: **142개 통과**. Node 계산 테스트 69개는 별도 실행했다.
- 공식 규정 미확인 상태에서는 자동 약가를 만들거나 오리지널·직접 입력값으로 대체하지 않음을 검증했다.
- 390·1366·1920px 화면에서 페이지 전체 가로 넘침을 확인했다. 큰 화면에는 입력을 모으고 작은 화면에서는 페이지 및 원료 표의 스크롤을 제공한다.

브라우저 테스트는 내부 HTTP 서버에서 수행했다. 이 클라우드의 Chromium 관리 정책은 `file://` 직접 실행을 `ERR_BLOCKED_BY_ADMINISTRATOR`로 차단하므로 이 경로와 실제 Windows 직접 실행은 검증 완료로 주장하지 않는다. 웹 파일은 상대 경로의 일반 HTML·CSS·JavaScript이며 외부 서버·API를 사용하지 않는다.

초기 웹 구현 검증 당시에는 GitHub Pages가 활성화되기 전이었다. 이후 공개 페이지 확인 결과는 아래 비용 구성 그래프 검증에 기록한다. 공식 약가 원문 조사는 [조사 기록](pricing-reference.md)의 접속 차단을 해결한 후 이어가야 한다.

## 비용 구성 그래프 수정 검증

```bash
node --test web/tests/engine.test.cjs
.venv/bin/python -m pytest web/tests/test_browser.py web/tests/test_cost_charts.py -q
```

- 계산·JSON 테스트 **69개**, 기존 화면 42개와 그래프 26개를 합한 브라우저 테스트 **68개**가 모두 통과했다.
- 기존 계산 결과를 보험약가 기준 도넛과 제조원가 기준 세로 누적 막대에 함께 연결했다. API → 부형제 → 포장재비 → 공수비의 순서, 동일 색상, 실제 구성비에 따른 높이와 원재료비 합계를 확인했다.
- 원료·약가·수율 변경, 시나리오 복제·전환 시 두 그래프의 갱신을 확인했다. 그래프 렌더링은 프로젝트 데이터를 변경하지 않으며 계산 엔진과 JSON 형식도 변경하지 않았다.
- 약가 미입력·0·음수·미확인, 제조원가 0, 약가와 같은 원가, 약가 초과, 비용 미완성과 매우 크거나 작은 값에서 오류·NaN·Infinity 없이 표시되는지 확인했다.
- 약가를 초과하는 경우 도넛만 제조원가 기준으로 전환했다고 명시하고, 중앙의 실제 약가 대비 원가율을 유지한다. 음수 차액은 회색 구간으로 표시하지 않는다.
- 390·1024·1440px 화면에서 라벨·비율·금액의 겹침과 잘림을 확인했다. 기본 계산 결과 화면을 실제 Chromium으로 렌더링하여 기존 카드 배치와 새 그래프를 확인했다.
- GitHub `main`에 반영한 뒤 공개 주소 `https://smoothsea45.github.io/project1/`의 HTML에서 새 그래프와 새 파일 버전을 확인했다. 공개 JavaScript·CSS는 로컬에서 검증한 파일과 바이트 단위로 일치했다.

## 표시 자릿수·포장형태·결과 및 비교 화면 수정 검증

- Node 계산·JSON 테스트는 기존 69개에 포장형태 6개를 추가하여 **75개 모두 통과**했다. 포장형태는 시나리오별 자유텍스트이며, 이전 schema 1 파일·브라우저 초안의 누락 필드는 빈 문자열로 보완한다. 계산 수식은 변경하지 않았다.
- 브라우저 전체 **82개**가 통과한 뒤, 실제 텍스트 기준으로 금액과 항목명의 간격을 더 엄격하게 검사했다. 이 검사에서 확인한 여백을 수정하고 관련 **16개**를 다시 실행해 모두 통과했다. 이 마지막 실행에는 복합제 비교 테스트 1개가 추가되어 전체 검증 범위는 **83개**다.
- 금액의 소수점 둘째 자리, 비율의 첫째 자리 표시를 결과 카드·원료별 계산·합계·비교표·그래프에서 확인했다. 입력 소수 자릿수와 저장 데이터, 반올림 전 계산값 및 그래프 비중이 유지되는지 확인했다. 작은 양의 비율은 `<0.1%`로 구분한다.
- 포장형태의 시나리오별 입력·복제 원본 유지·JSON 저장 및 열기·초안 복원·기존 파일 호환을 검증했다.
- 결과 카드의 약가 → 제조원가 → 원가율 순서와 약가 계산 근거 영역 제거를 확인했다.
- 비교 18행의 순서, 각 비용의 배치당·1T당 값, 복합제 API별 제조원과 원화·달러 단가를 확인했다. 결과와 비교 그래프는 동일한 렌더러에 각 시나리오의 실제 계산 결과를 전달하며, 값 변경·시나리오 전환·0·미완성 입력을 확인했다.
- 390·1024·1440px의 라벨·비율·금액 겹침과 잘림, 큰 금액, 데스크톱 그래프 확대, 항목명과 금액의 실제 텍스트 간격 및 약가 선택 행의 정렬을 확인했다. 입력·결과·비교 화면을 실제 Chromium으로 렌더링하여 배치를 확인했다.

## 결과 좌우 배치·시나리오 탭·비교표 출력 검증

- Node 계산·JSON 테스트 **81개 모두 통과**. 프로젝트 생성·복제·JSON 읽기/쓰기에 시나리오 4개 제한을 적용했다. 초과 요청 시 원본·선택 시나리오 유지와 복수 가산 체크의 저장·불러오기를 확인했다. 계산 수식과 약가 자동 산정 모듈은 변경하지 않았다.
- 브라우저 검증 **93개 통과**. 기존 83개 중 81개 통과 후 인쇄용 제목 및 직접 입력 표시의 DOM 선택자를 수정한 2개와 신규 10개를 다시 실행해 12개 모두 통과했다.
- 결과 카드 약가 → 제조원가 → 원가율의 세로 배치, 오른쪽 실제 데이터 그래프, 원가율만 강조하는 표시와 390·1024·1440px의 가로 넘침·그래프 잘림을 확인했다.
- 시나리오 탭 클릭·키보드 이동·독립 데이터, 4개 도달 시 복제 제한·삭제 후 다시 추가, 초과 JSON 열기 시 현재 프로젝트 및 초안 유지, 초과 브라우저 초안 복원 거부 시 원래 문자열 보관을 확인했다.
- 약제별 가산 6개 항목의 독립 체크·해제·복수 선택 저장, 제목 옆 직접 입력 고정 표시, 기존 자동 모드 파일의 직접 입력 전환과 입력 금액 보존을 확인했다.
- 비교표는 시나리오마다 배치당·1T당 두 열로 묶으며 API·부형제·포자재·공수 비용이 각각 같은 행에 정확히 표시되는지 확인했다. 일반 정보와 각 그래프는 시나리오의 두 열을 합쳐 표시한다.
- 출력 버튼의 브라우저 인쇄 호출과 프로젝트 불변성을 검증했다. Chromium으로 실제 4개 시나리오 A4 가로 PDF를 만들고, 비교 전용 화면·모든 항목과 금액·도넛 및 막대의 표시·텍스트 좌표가 용지 안에 있는지 확인했다. 이 환경의 예제 PDF는 2페이지이며 헤더가 반복되고 그래프와 비용은 잘리지 않았다. 실제 Windows 프린터에서 종이 출력은 수행하지 않았다.
